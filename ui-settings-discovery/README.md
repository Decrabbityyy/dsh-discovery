# dsh-client-ui-settings-discovery

`dsh-client-ui-settings-discovery` 在 DeepSeek Harness Web 设置中增加「模型发现」页面，包含两个区域：端点探测与 Provider 采纳、动态路由管理。

本插件依赖 [`dsh-llm-discovery`](../llm-discovery/README.md) 提供的 models.dev 目录服务。没装它时本插件的宿主半边不会激活，页面读不到目录；装上它之后才有探测与采纳区域。再装 [`dsh-llm-dynamic-provider`](../llm-dynamic-provider/README.md)，才会多出动态路由区域。

页面读 Host 的插件清单来决定显示哪些区域：宿主插件已启用且成功加载，对应区域才会出现。这只是插件状态读取，不是模型端点探测；用户不需要配置或访问任何特殊地址，只需在实际探测时填写真实的 `baseURL`。

插件自身的 Host 半边把目录服务的结果交给浏览器半边：`/ui-settings-discovery/catalog` 回答整份目录（思考档位、输入/输出模态、名称与容量），`/ui-settings-discovery/catalog/status` 回答目录状态（`POST` 会重新读取目录）。没有 Web 服务器时不注册这两个端点，插件卸载时随之撤销。浏览器半边在同一页面会话里只抓一次目录，「模型发现」页与「模型与选项」弹窗共用它。

除「模型发现」页面外，本插件还在「设置」→「插件」里贡献一个「模型目录」页面（排在「插件配置」与「插件列表」之后；没装 `dsh-llm-dynamic-provider` 时页面会直接说明）。它显示声明路由数与 models.dev 目录的条数、刷新时间、来源，提供「刷新目录与路由」按钮（不等重启就重新读取目录、重新探测所有路由，并逐条列出每条路由的模型数或失败原因），以及一个「目录自动刷新间隔」输入框：宿主服务了 `llm-discovery` 命名空间时出现，保存后立即重排目录定时器，不用重启。停在页面上时，它按宿主报的「下一次刷新时刻」重读一次状态，所以后台刷新完不用手动点也会显示出来；只在挂载时刷一次的部署没有下一次，页面也就不会再发请求。

标准 Web profile 需要提供 Host 的 `plugin-inventory`，并使用能够挂载 `remote.llm`、`remote.settings`、`remote.credentials` 与 `remote.pluginInventory` 的匹配版本 `api-remotes`；不要混用不同发布系列的 Host 与 Client 包。清单 Remote 不可用时页面会隐藏这两个区域；这表示运行时状态未知，不等同于宿主插件一定未安装。

## 安装

`dsh-llm-discovery` 是本插件的前置依赖，先装它，再装 UI：

```sh
dsh plugin --profile web add dsh-llm-discovery
dsh plugin --profile web add dsh-client-ui-settings-discovery
```

需要动态路由管理时，再装：

```sh
dsh plugin --profile web add dsh-llm-dynamic-provider
```

最后确认两个（或三个）插件都进了配置：

```sh
dsh --profile web --dump-config
```

启动 Web profile 后，打开「设置」→「模型发现」。

## 探测并采纳模型

1. 选择一个预设：Ollama、LM Studio 或 llama.cpp，端点地址会自动填好（分别是 `http://127.0.0.1:11434/v1`、`http://127.0.0.1:1234/v1`、`http://127.0.0.1:8080`）。其他服务选择「自定义端点」并填写它的 API 根地址，例如 Gemini 用 `https://generativelanguage.googleapis.com/v1beta`。
2. 选择协议：
   - OpenAI Chat Completions：`openai-completions`
   - OpenAI Responses：`openai-responses`
   - Anthropic Messages：`anthropic-messages`
   - Google Gemini：`google-generative-ai`
3. 输入 API 密钥；本地无认证端点可以留空。
4. 点击「探测」。
5. 检查返回的模型，取消不想添加的条目。
6. 目录没自动认出来的行，点它「名称」旁边的「匹配目录」指定它的目录条目，见下一节。
7. 填写路由 ID。只能使用小写字母、数字和连字符。
8. 可选填写显示名称。
9. 点击「采纳为 Provider」。
10. 到「模型」设置页查看并使用新 Provider。

如果填写了 API 密钥，页面会把它保存到凭证存储，并让 Provider 引用该凭证；密钥不会写进普通 settings 配置。

采纳时，页面会按**每个模型**写入它自己的能力声明：models.dev 记录该模型接受图片输入时，条目会带上 `input: [text, image]`，这个模型之后才能接收图片附件或使用 `read_image`。目录没有记录、或只记录文本的模型不写 `input` 字段——该字段在界面上没有别的编辑入口，写死成纯文本反而会让模型以后无法接受图片。表格里显示的、端点没披露的名称、上下文窗口和最大输出也一并写入，这样模型选择器里显示的是名字而不是原始 id。路由 ID 命中已安装 pi-ai 提供方时（例如 `anthropic`），模态和思考档位一样交由安装目录决定，页面不写入。

## 目录匹配

表格每行的「名称」旁边有一个「匹配目录」按钮，它决定这一行从 models.dev 的哪一条读取名称、上下文窗口、最大输出、模态和思考档位。

目录按 models.dev 记录的 id 建键（`glm-5.2`、`x-ai/grok-4.6`），同时也收录去掉厂商前缀的裸名，所以带前缀和不带前缀的 id 都能落地。自动解析依次尝试整个模型 ID、第一个 `/` 之前的部分、最后一个 `/` 之后的部分，忽略大小写：整个 ID 命中优先，因此 `x-ai/grok-4.6` 用 openrouter 记的那条，不会被裸名条目盖住；`Gemini-3.7-Flash/Antigravity` 落到 `gemini-3.7-flash`（这里的 `/` 是变体标记，不是厂商前缀）。两个候选同时命中时不自动选择——猜错会把别的模型的模态与档位写进这一行——按钮保持「匹配目录」，由你指定。

点开「匹配目录」是一个可搜索的条目列表：

- 每行给名称、收录它的 provider 标签，以及一行摘要。
- 摘要形如 `256k/33k · 文·图 · □□□■□■`：容量用缩写（缺少的那一个不写），接着是模态，最后六个方块依次代表 minimal / low / medium / high / xhigh / max（`off` 不占位，没记录档位就是六个空格）。悬停可以看到精确容量与这条记录的全部档位。
- 同一个 id 被多家收录时，数值一致的合成一条，标签写成 `zai-org 等 2 家`（悬停列出全部名字）；数值不同的各自单列一条，靠标签与容量、模态、档位区分，你选哪条就用哪条的数值。
- 行上不显示模型 id：搜索照旧按 id 匹配，悬停在名称上会给出这一条对应的 id。
- 搜索匹配 id、名称与 provider 名。`@zai` 只列出来源含 `zai` 的条目，多个 `@` 之间是「或」，也可以和文本混写，例如 `glm @zai`。
- 搜索框默认填入该 id 的最长已收录前缀：`deepseek-v4-flash-max` 打开时已经筛到 `deepseek-v4-flash`，`glm-5.2-fast-preview/cc` 筛到 `glm-5.2`，选一条即可。
- 选定后按钮变成「目录」，悬停显示是自动匹配还是手动匹配以及对应条目；「清除匹配」回到自动解析。绑定只作用于当前页面会话，写进 profile 的是它带来的那些字段，所以重开页面后看到的是已经写好的名称与容量。

手动绑定会把这一行的名称、上下文窗口、最大输出、模态与思考档位都换成该条目的：手动指定的条目连名称与容量一起作数，自动解析的只在端点没披露时补。档位不由你挑，采纳或保存时按该条目全量写入（配置里已声明的档位一并保留）。

## 字段说明

| 字段 | 说明 |
|---|---|
| 端点地址 | 模型 API 的 baseURL，不是控制台或文档页面地址 |
| 协议 | 端点实际接受的请求格式；选错会导致探测或对话失败 |
| API 密钥 | 探测和后续模型请求使用的凭证 |
| 路由 ID | Provider 的唯一标识，例如 `local-ollama` 或 `company-gateway` |
| 显示名称 | 模型设置和选择器中显示的名称 |
| 思考档位 | 只读标注：这一行支持哪些 reasoning effort（写成 `off/low/high` 这样的文字），保存时全量写入 |
| 匹配目录 | 指定结果表某一行用 models.dev 的哪一条记录；详见「目录匹配」 |

结果表里的「模态」列（`文`、`图`）与采纳时写入的多模态声明来自同一份 models.dev 目录。

如果路由 ID 已存在，页面会拒绝覆盖。请到「模型」设置页编辑已有 Provider。

## 在模型页编辑已有提供方的模型

「模型」设置页里，属于 `llm-pi-ai` 命名空间的提供方卡片点开「编辑」后，卡片里会出现「模型与选项」按钮，打开一个弹窗；卡片收起时这个按钮不显示，不占位置。弹窗的内容：

- 弹窗读取该提供方已保存的配置：端点与协议取自 profile，API 密钥仍由宿主按原引用解析，所以不需要重填路由 ID 或密钥。
- 表格列出该提供方**显式声明**的模型（模型全部来自安装目录的路由在这里是空的）。点击「探测端点」会按已存的端点与协议询问模型清单，新出现的模型以未勾选状态加入，勾选后随「保存」写入。
- 每行的「匹配目录」和发现页是同一个控件：解析不出来或解析错了的行可以在这里指定它对应 models.dev 的哪一条。
- 思考档位只**标注**：表格列出「匹配到的条目记录的 + 配置里已声明的」全部档位（如 `off/low/high`，表头悬停说明会全量写入），保存时写入的就是这些，不需要（也不能）逐档勾选。模态声明按该条目的图片支持写入 `input`，条目没记录时保留配置里的原值；名称与容量同样以该条目补端点没披露的部分。
- 「保存」把选中的模型写回 `llm-pi-ai.providers.<路由>.models`，写入的 revision 是打开弹窗时读到的；其他页面同时改过这个提供方时保存会被拒绝，重新打开再改即可。
- 弹窗打开期间把卡片收起不会关闭弹窗；弹窗是模态的，关闭它即可回到卡片。

入口只在卡片展开时出现，这一判断由插槽内容读取所在卡片的结构完成：Models 页把扩展区渲染在卡片里、编辑器之前，并且不告诉扩展区卡片是否展开。宿主改变卡片结构时入口的显示可能失效，见「已知限制」。

## 管理动态路由

安装 `dsh-llm-dynamic-provider` 后，页面会显示「动态路由」区域。

1. 点击新增路由。
2. 填写路由 ID、端点、协议和可选显示名称。
3. 端点需要认证时输入 API 密钥。
4. 保存后等待探测完成。
5. 探测成功后，该路由的整个模型目录会出现在模型选择器中。

删除动态路由会移除该路由注册的模型，但不会删除凭证存储中已经保存的密钥。

编辑已有动态路由时，如果它使用凭证，请重新输入 API 密钥；当前版本不会在编辑表单中回显旧密钥，留空保存等于让该路由不带凭证。表单里也没有 `defaultContextWindow` 与 `defaultMaxTokens`，用页面编辑会清掉这两个值，需要它们时请在 `settings.yaml` 里维护。

## 常见问题

### 页面没有显示探测表单

确认 `dsh-llm-discovery` 已启用且成功加载，并检查 Web profile 的插件清单（「设置」→「插件」）中是否存在 active 条目。`dsh --profile web --dump-config` 只能确认配置层有该插件，不能证明它已成功启动。若 Host 的 `pluginInventory/list` 不可用，页面也会按安全策略隐藏区域；这不等同于插件未安装。只有 UI 插件时无法探测。

### 点击探测后显示认证错误

检查 API 密钥、协议和 baseURL 是否属于同一个服务。Anthropic 与 Gemini 不能使用 OpenAI 协议地址进行原生探测。

### 探测成功，但模型对话失败

检查采纳后的 Provider 配置。Ollama 地址必须包含 `/v1`；协议必须与服务实际支持的生成接口一致。照抄预设或上游文档给出的 API 根地址最稳妥。

### 思考档位或模态信息为空

页面从 models.dev 补齐这些信息，数据由插件 Host 半边提供，页面打开时抓一次。模型不在该目录里（自建端点的私有模型名、目录还没收录的新模型），或者目录不可用（网络不通），这一列就是空的。变体 id（如 `deepseek-v4-flash-max`）需要点该行的「匹配目录」指定它的基座条目，详见「目录匹配」。安装 `dsh-llm-dynamic-provider` 只会影响「动态路由」区域，不再是这些信息的来源。

### 其他页面刚修改的配置没有立即出现

重新打开「模型发现」页面，或者重新执行一次探测。当前页面不接收其他设置页面的实时更新。

## 已知限制

- 页面创建 Provider 后，只能到「模型」设置页继续编辑。
- 「模型与选项」保存的是该提供方的显式 `models` 列表：对模型全部由安装目录提供的路由（例如 `anthropic`）来说，这等于把清单固化下来，之后安装目录新增的模型不会自动生效。
- 档位不能收窄：写进配置的 `reasoningEfforts` 是「匹配到的条目记录的全集 + 原配置里已声明的」，界面上不提供逐档开关；要收窄只能编辑 `settings.yaml`。
- 模态声明只写入、不能逐字段编辑：它来自该行匹配到的目录条目，要改就换一个条目；目录里没有的写法只能编辑 `settings.yaml` 里 `llm-pi-ai.providers.<路由>.models` 对应条目。
- 目录条目的容量与模态就是收录它的 provider 记录的那份：数值一致的几家合成一条，数值不同的各自单列，所以条目显示的就是写进配置的那份，不会出现「用了别家数值」的静默替换；对不上时换一条条目，或直接编辑 `settings.yaml`。
- 目录匹配是「这一行用哪条目录数据」的选择，不会改写模型 ID 本身：写进配置的 `id` 仍然是端点给的那个（`glm-5.2-fast-preview/cc` 还是它自己），只有名称、容量、模态与档位取自所选条目。
- 匹配到的条目如果记了图片输入而这个变体其实不支持，`input: [text, image]` 会被写进配置：这是对端点的断言而不是探测结果，对话中可能被提供方拒绝，改用正确的条目或编辑 `settings.yaml` 即可恢复。
- 「模型与选项」入口的显示依赖 Models 页当前的卡片结构：扩展区在卡片里、编辑器之前，且卡片里除编辑器外没有别的表单控件。宿主若改变这个结构，入口可能一直不显示；扩展区找不到插槽锚点时按展开处理，入口照常显示。
- 协议列表是固定的四种协议。
- 路由 ID 以数字开头时不能保存 API 密钥：派生出的 `<ROUTE>_API_KEY` 不是合法的环境变量名（凭证引用必须是 POSIX 风格的名字），页面会拒绝保存并给出原因。不带密钥的路由不受影响，也可以改用字母开头的路由 ID（例如 `ai-302`）。
- 连续快速保存动态路由可能触发重叠探测；一次保存后请等待结果再继续修改。
- 宿主插件状态来自一次性的插件清单快照；启用、停用或热替换插件后，请重新打开页面以刷新可见区域。

## Model Experience

本插件只提供浏览器配置界面，不向模型请求添加内容。

#### KV Cache 影响

无。插件不组装或发送模型请求。
